# RTL Harness 使用说明

本页只回答“现在该怎么用”。若想理解本地/服务器/Docker 的分工和数据流，请看
[工程架构说明](工程架构说明.md)。

## 通过标准

一次 run 必须同时满足：仿真正常完成、状态字为 `0x600dd00d`、每个 token 的 logits cosine
不低于 `0.98`、argmax agreement 不低于 `0.99`。

Verilator 显示 `PASS` 只代表 RTL 程序运行结束；是否通过以 scorer 的 cosine/argmax 为准。

## 1. 进入工程

```bash
cd /Users/chenzikang/code/work/RTLharness
```

## 2. 手动验证一次 baseline

当前问题首错在 prompt 1 的 pos2，因此先验证包含 pos0～pos2 历史状态的 3-token 前缀：

```bash
bash scripts/remote_round.sh \
  --task 01_repair_multitoken_golden \
  --seed 20260706 \
  --prompt 1 \
  --seq-len 3
```

它结束后会在本地生成 `runs/<run-id>/feedback.txt`。完整 image、dump、编译产物和完整日志
保留在服务器。

## 3. 启动 DeepSeek 自动迭代

先使用 3 次尝试观察行为：

```bash
python3 harness/agent_loop.py \
  --task tasks/01_repair_multitoken_golden.md \
  --adaptive-prefix \
  --initial-seq-len 3 \
  --max-attempts 3
```

确认行为正常后，把 `--max-attempts 3` 改为 `10`。

自动策略是：3-token 前缀通过后立即回归完整 16-token prompt 1；若完整 run 的首个 route
分叉在 posN，下一轮改为 pos0～posN 的 N+1-token 前缀。

再次启动时，DeepSeek 会读取当前 RTL、最新反馈、最近 3 轮详细交接，以及所有历史轮次的
极简索引；它不会重新从 baseline 开始，也不会把整篇历史 diff 塞进上下文。

不要同时手动启动相同任务的 `remote_round.sh`。DeepSeek 只修改 `rtl/`，controller 负责
上传、仿真、评分和自动诊断。

## 4. 观察进度

另开一个终端，实时查看当前最新一轮 AI 输出：

```bash
cd /Users/chenzikang/code/work/RTLharness
LATEST_AGENT=$(find runs -maxdepth 1 -type f -name agent.log | sort | tail -1)
tail -f "$LATEST_AGENT"
```

每次启动自动迭代都会生成唯一 session-id；每个 session 内再有 `attempt-1`、`attempt-2`
等目录，因此旧日志、快照和 diff 不会被后一次启动覆盖。`Ctrl+C` 只退出查看。

新目录名会携带关键信息，便于人工辨认。例如：

```text
01_repair_multitoken_golden--20260821-140143--p0--full--7618
agent-01_repair_multitoken_golden--20260821-141000-12345--p0--adaptive--attempt2
```

前者是一次远程验证（任务、时间、prompt、验证范围、进程号）；后者是一次 AI 修改轮次。
`full` 表示完整序列，`prefix13` 表示前 13 个 token，`adaptive` 表示由 controller 自适应决定前缀。

查看服务器状态：

```bash
bash scripts/remote_status.sh
```

以下命令只供你人工实时观看服务器日志：

```bash
bash scripts/remote_status.sh --follow
```

`Ctrl+C` 仅停止观看。不要让 DeepSeek 调用 `--follow` 或 `tail -f`，否则 AI 会等待一个不会
自动结束的命令。若状态已是 `failed`、`passed` 或 `cancelled`，`--follow` 会明确提示没有可
跟随的实时仿真；此时查看本地 `agent.log`，等待下一次服务器 run 启动。

## 5. 查看结果

每轮迭代的汇总报告：

```bash
tail -n 120 reports/01_repair_multitoken_golden/progress.md
```

`progress.md` 每轮同时保存两类内容：上方是修改文件、评分和诊断等结构化结果；末尾的
“AI 可见工作记录（agent.log 原文）”是 OMP/DeepSeek 实际输出的分析与修改说明。它不是
模型不可见的内部推理，但足以审阅 AI 如何定位问题、为何修改以及它预期的结果。原始单轮
日志仍保留在各轮的 `runs/agent-.../agent.log`，便于需要时逐字核对。

最新单次验证的紧凑反馈：

```bash
LATEST=$(find runs -maxdepth 1 -type d \
  -name '01_repair_multitoken_golden-*' | sort | tail -1)
cat "$LATEST/feedback.txt"
```

`feedback.txt` 只会在远程 run 结束后出现；运行中请看 `remote_status.sh`。

## 6. 停止与取消

正在前台运行 `agent_loop.py` 时，按 `Ctrl+C` 停止本地 AI/controller。然后检查服务器：

```bash
bash scripts/remote_status.sh
```

若仍是 `running` 或 `diagnosing`，先预览、再取消当前 run：

```bash
bash scripts/remote_cancel.sh --dry-run \
  --task 01_repair_multitoken_golden

bash scripts/remote_cancel.sh \
  --task 01_repair_multitoken_golden
```

该脚本不会停止 Docker 容器，也不会影响其他服务器项目。

## 7. 需要额外诊断时

顶层失败后自动运行 `auto` 诊断。需要额外证据时才手动执行：

```bash
# 审计每个 token 的 L0/L1 top-2 route
bash scripts/remote_diagnose.sh --action routes

# 对拍 KDA、L0 router、MLA cache/context 的连续向量
bash scripts/remote_diagnose.sh --action snapshots

# 仅用于真正的单-token run
bash scripts/remote_diagnose.sh --action one-token
```

## 常用脚本速查

| 文件 | 用途 |
| --- | --- |
| `harness/agent_loop.py` | 日常自动修复 |
| `scripts/remote_round.sh` | 手动跑一次服务器验证 |
| `scripts/remote_status.sh` | 查看服务器当前状态 |
| `scripts/remote_cancel.sh` | 安全取消当前服务器 run |
| `scripts/remote_diagnose.sh` | 手动补充有限诊断 |
