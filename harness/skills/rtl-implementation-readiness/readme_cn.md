# RTL implementation readiness v2

这个模块放在初版 RTL 生成之后，解决需要真实工具小实验才能判断的问题：过程展开太慢、重复运算在不同阶段的复制与合并、存储器推断、选择逻辑深度，以及共享和复制的取舍。目标是缩短“发现问题—修改—验证—重新综合”的闭环，不承诺局部最优能得到全设计最优。

它可以单独使用。调用模型负责读代码、提出假设、编写候选；目录内 Python 标准库脚本负责冻结输入、分析线索、预算内执行、身份校验、比较和导出。无需另一个实现 skill、审阅 skill、微架构 skill、项目 adapter、外部模型命令服务或上级目录 runtime。需要时，把普通证据和补丁交给这些模块即可。

默认不修改用户源码，不自动启动大综合。每个实验从冻结树生成独立工作副本，记录工具、源码、参数、命令、日志和测量。重复提交同一作业身份只查询，不重跑；超时只清理自身实验进程组；失联不会自动“断点继续”。

分析器是有范围的文本启发式，不能算出最终门数或精确耗时。真正决策来自同范围的工具测量和功能验证。比较默认看三次测量、中位数改善及区间是否分离；不足时保留原版或给出证据不足。共享导致的扇出、选择器、面积和时序代价需要根据实际统计继续判断，不能只看小模块编译更快。

交付包含候选补丁、冻结身份、实际实验记录和结论。未验证提案仍可导出供讨论，但明确标成 proposal-only；它不是获准集成的候选。推荐候选也只适用于测过的范围，不代表映射面积、顶层 STA 或物理实现通过。

v2 不兼容旧版 controller/observation/事务状态 API。旧版文件单独归档，历史 shadow 结果保留；既有 harness 未自动升级。新项目可以直接调用 CLI，也可以用薄适配层把明确的源码、参数和命令传入。用法见 [SKILL.md](SKILL.md) 和 [commands.md](references/commands.md)。
