# Microarchitecture audit

Audit a frozen unified architecture.md and structured evidence for entry into RTL exploration: resource organization and critical choices need a defensible basis, with no known contradiction likely to force major architectural rework. Do not rewrite the proposal. The frozen original input closure—primary spec/reference and any declared `support/<input-relative-path>` helpers/configuration—defines requirements and computation semantics; designer extraction, arithmetic and historical outputs are fallible claims. Follow relevant helper/configuration definitions. A noncanonical reference entry may appear both as `reference.py` and under its original support path; this is one computation, not two. Python functions do not prescribe hardware instances. Assume no project dimensions, operator names, entry functions, interfaces, reset policy, ABI, budgets or preferred organization.

Use separate source-only and proposal-audit contexts. This skill owns independent engineering review; the caller owns input freezing, model/tool execution, evidence versions, retry limits and release. Read [references/source-baseline.md](references/source-baseline.md) for source declarations and repairs, or [references/review-contract.md](references/review-contract.md) for proposal tools and report delivery. A script success proves the declared relationship, not source interpretation, complete hardware correctness or physical closure.

## Source-only entry: establish independent witnesses

Only the same frozen original input closure is available, with no design context. Build a compact baseline before seeing the proposal:

1. Trace required effects, shapes, loops, data dependencies, state lifetime/freshness, numerical acceptance, interfaces and completion. On a few decisive state/reduction paths, retain key intermediate value versions and transformations in existing semantics/basis or obligation prose; prior/intermediate/committed values may have different consumers. Independently identify input-defined service, latency and backpressure; a peak rate does not guarantee readiness. Separate obligations from preprocessing and record ambiguities without choosing hardware.
2. Identify the input's evaluated workload extents separately from maximum legal state/capacity domains. Choose decisive paths, then fix one real outer iteration of each source expression. Recover operand ranks/shapes after slicing and the contraction/reduction axes before selecting a primitive. Record this short source trace in the existing semantics/basis. Separate single-instance work from remaining outer repetition, map both to the supported primitive/scope recipes, and run `scripts/source_model.py`. Check returned extents and scope factors against the trace; sequential primitives add and each outer/prefix axis is applied once. Keep scalar effects and MACs separate.
3. Declare logical state shapes and lifetimes at the maximum legal configuration where capacity matters. These are logical elements, not an imposed FP32 cache or an on-chip requirement. Mandatory fixed external fields have source-defined bit widths; compute their bytes by fields and scope. Mark designer-selectable lossless encoding as ABI-dependent without freezing a byte count. Include loading, initialization effects, output and DONE/handshake obligations even when they have no arithmetic primitive.
4. Deliver source obligations and executable witnesses together. Identify omitted or unsupported paths and the semantic review still needed. Calculation feedback may require correcting the source interpretation; preserve the distinction between that error and a defect in the candidate.

This is a fallible independent source interpretation, not a second architecture or a compiler. Direct-reference counts are not universal hardware lower bounds: valid fusion, algebraic transformations, recomputation and numerical choices may change realization costs. Do not turn reference storage or execution order into invented requirements.

## Proposal entry: rebuild the critical argument

A separate context receives the originals, independent source baseline, proposal and actual calculation evidence. The baseline is a fallible source interpretation. Before comparing a row, recover its original expression, operand ranks after slicing, contraction axes and remaining repetition. Match semantic effects rather than IDs or node boundaries. An inventory disagreement first needs the actual matrix axes and complete tensor set, not a candidate change to fit the auditor's mistaken selector. Valid local receipts survive unrelated declaration failures; failed dependencies cannot supply evidence.

Work through the following passes, concentrating depth on the paths that determine correctness, capacity or claimed throughput. Account for the remaining source obligations in the report, grouping related effects where appropriate. Representative paths, coarse schedules, conservative utilization and explicit estimate ranges are acceptable when their basis supports the resource and budget argument. Do not require exhaustive executable count/profile/operand coverage, a full-lane trace of every resource, every tail controller, or full bit-accurate regression. A decisive structural defect supports `revise` without completing unrelated review.

### 1. Reconstruct dependencies before trusting costs

Choose the few dominant or correctness-critical compute/state/reduction paths; fix one real iteration before expanding scope. Independently reconstruct the source's key value versions, transformations and consumers. Then reconstruct the proposal's chain from its dataflow, schedule and prose before comparing them; do not reuse the source chain as an assumed description of the proposal. An entry/exit or old/new-state match does not prove that a consumer received the required intermediate version.

Compare each consequential edge: which exact version enters the transform, which result feeds the consumer/reduction/normalizer, and which old or intermediate values must remain live? Check `work.dependencies` as a fallible declaration, not the definition of the proposed execution. Record the short source/proposal correspondence and any differing consumed version in existing report `requirements.explanation` or evidence prose. When useful, execute a small source-legal value example distinguishing the two chains; matching operation totals or an acyclic graph cannot close a semantic discrepancy.

Accept a credible architecture-level ordering/retention mechanism without demanding exact pipeline handshakes. Legal fusion, streaming, reordering, retained rows and recomputation may avoid materializing intermediates, but must preserve the consumed mathematical values and chosen numerical behavior; do not reject them solely for different node boundaries or storage. For a real overwrite, identify the remaining consumer and actual retained location/lifetime. Resolve a source-backed value-version or ordering contradiction as a design finding even when arithmetic, area and DAG checks pass.

### 2. Challenge the main resource and supply argument

Choose representative paths that determine the compute, bandwidth or state-update budget. Rebuild their operand shapes, mapping to lanes/words, broadcast or retention, required ports and update ordering. A typical tile or issue plus an explained repetition rule can be enough; a one-lane example alone cannot establish an unexplained full-rate claim. Ask whether the claimed aggregate rate has a credible supply mechanism and cost, rather than requiring every lane to be explicitly enumerated. Use compact execution rules and inspect expanded events where they resolve a material doubt.

Reconcile coarse load, compute/reduction and commit phases with task scope and simultaneous storage. Follow principal operand/traffic demand through its service bound to the interval actually charged in the budget; detached passing checks do not establish that correspondence. For data called preloaded, read the original RUN measurement/completion boundary before allowing its transfer cost outside the task; the label alone grants no exemption. Include significant setup, wait, reduction, writeback and tails once, with calculated costs or conservative allowances. An explained rate/utilization range can support a draft; unexplained ideal operation/rate division cannot. Complete execution costs replace corresponding coarse charges rather than duplicate them. Detailed control may remain RTL work when its resource and cost implications are bounded.

For nonlinear resources inspect the chosen numerical method, domain, rate/latency estimate and sharing. A target clock alone does not justify a deeply combinational operation's rate. Conservative algorithm or pipeline estimates with uncertainty can support a draft without committing every pipeline register. Check storage for simultaneously live values and include it in capacity/area. Block a known overwrite or capacity deficit; do not require a complete register-transfer trace to accept a plausible retained-row mechanism.

Use `check_proposal` or `recompute` where a deterministic count, flow, service or operand witness would decide the review. These tools are available for focused evidence, not an exhaustive delivery checklist. For transformed realization, examine semantic/numerical correspondence and its native cost basis; neither matching source counts nor a transformation label proves equivalence. Compare shared-resource demands without forcing independent resources to serialize. A necessary service bound is useful evidence but is not a cycle-accurate schedule. Preserve legal fusion, broadcast, sharing and overlap rather than imposing a preferred topology.

### 3. Exercise transition and numerical boundaries

Inspect where the proposal converts or changes ownership of data, using small executable probes for decisive arithmetic rather than mental totals:

- **Load/ABI:** independently rebuild fields, tensor inventory, encode/decode, row/axis order, assembly storage and writes. Use representative boundary points when the chosen packing or legal shape range could change capacity, semantics or transfer costs; do not require a complete tail-controller proof. Tie the actual load/unpack/write walk, initialization and output drain to charged cycles and ports. Distinguish valid payload, padding and wire transactions; lossless rearrangement is permitted. For nonbyte fields use complete-task bit-packing bounds unless the chosen ABI imposes extra padding. An undefined encoding or boundary policy that threatens valid data or the main budget is a design gap; detailed tail-control implementation can remain downstream when legal elements and bounded cost are accounted for. An auditor request that omitted an already specified policy is an audit gap.
- **Lifetimes/completion:** compute simultaneous logical state at the largest legal capacity domain using the selected formats, copies, padding and placement. Test permitted alias/spill/recompute against actual lifetimes. Inspect run-boundary freshness, outstanding responses, backpressure, accepted writes and completion. Fresh logical state does not mandate physical reset or bulk zero writes.
- **Numeric boundaries:** follow formats through product, accumulation, rescaling, rounding, clipping and selection. Independently choose legal probe points and assertions for applicable small constants, quantization to zero, denominator behavior, overflow and output conversion. Inspect actual scalar/row results and failed assertions; empty probes mean not checked, and calculations without assertions do not establish a pass. Neither an arbitrary probe quota nor rerunning the designer's exact points establishes risk coverage. Distinguish real-valued invariants from quantized ones: positive real values can round to zero, and monotone quantization can create selection ties. A probe outside a proven reachable domain does not establish a functional failure; state the reachability premise. The architecture needs a coherent format/domain and boundary behavior on critical paths; full bit-accurate/reference regressions, approximation characterization and RTL numerical execution can remain downstream. Representative probes give point evidence, not range or end-to-end proof.
- **Emitted outputs:** retain original carrier/interface and scale permissions when judging an alternative encoding. Recompute representative rows through the specified scale, rounding and overflow rule. Check required metrics on decoded emitted values and derive reported selection from the actual emitted row with the specified tie rule. Positive scaling before quantization may create ties; later scaling cannot repair discarded precision. Distinguish output conversion evidence from unperformed internal fixed-point accuracy regression. Reconcile changed widths/scales with layout, storage, traffic and conversion cost.

A counterexample states the original obligation, concrete candidate mechanism/value, computed consequence and testable closure criterion. A blocking missing choice explains why RTL exploration would otherwise need to invent or reverse a major resource, state, interface or numerical decision. A finer pipeline or control detail is not blocking merely because it remains undecided. Do not demand one particular fix. Compare actual inventory plus logic/register/FIFO contributions, cost provenance and uncertainty against hard budgets; program-derived macro area need not be duplicated as a manual row. Keep optimization targets distinct from hard limits. Estimated clock-frequency throughput and uncalibrated area are estimates, not synthesis or physical closure.

### 4. Execute focused evidence and report the correct boundary

Use remaining tool allowance on the unresolved question most likely to change the verdict; batch independent count/flow/service/operand/ABI/numeric checks with the right originals and proposal references. Repair a mistaken selector/formula by executing the related corrected relationship. Do not treat a prose acknowledgement or an unrelated passing calculation as closing an earlier failed comparison. Record every binding-verified failure with its actual disposition. A complete inventory deficit requires a real design finding or a concrete source/profile correction; it cannot disappear into a general coverage disclaimer. Check the revision's impact beyond the named finding: dependencies and lifetimes after a schedule change, or layout/traffic/cost and actual emitted selection after an output-format change.

Classify each remaining obligation by what is actually absent:

- `design_decision`: a consequential resource/supply, ordering/lifetime, capacity, numeric or ABI choice is absent or contradictory, so the main correctness or budget argument cannot be assessed without substantial architectural work. Cite the source/proposal, consequence and testable closure criterion; return `revise` with an open blocking finding. Missing exhaustive traces or receipts alone do not establish this defect.
- `audit_evidence`: a critical unresolved review question prevents judging source semantics, state safety, major supply/capacity or a hard budget. Name the question and next audit action. Without an independently supported design defect, this yields `insufficient_evidence`. Incomplete optional tool coverage alone does not justify it.
- `implementation_evidence`: the architecture has a credible resource organization and critical behavior, while detailed pipeline/arbitration/tail control, full cycle/stress or bit-accurate regression, or timing/library validation remains. Identify that basis and the remaining proof. This label cannot hide a known contradiction or an undefined critical numerical path.

Known source-semantic/lifetime errors, a capacity or major supply/budget argument that does not hold, and undefined critical numerical behavior require revision. Conditions and optional improvements alone do not. Accept means the draft is reasonable for RTL exploration under stated estimates/conditions, not that implementation or tapeout readiness has been proved. The report must address original obligations and hard limits, close known blocking findings and explain unresolved implementation work. Acceptance still needs at least one actual same-packet, binding-verified `check_proposal` child transaction and independent numerical observations on decisive claims. `coverage_complete` and exhaustive count/profile/flow/operand execution are not acceptance criteria. Preserve and adjudicate every executed contradiction, including auditor declaration errors. Return only the report selected by the caller's current step. The caller owns release and finite retries. Do not edit the proposal, alter inputs, or run RTL/Readiness/PPA work.
