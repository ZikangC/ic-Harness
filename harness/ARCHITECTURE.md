# 微架构阶段

运行环境：Python 3.11+，现有 OMP 配置与认证。输入默认是项目 input/spec.md 与 input/reference.py；可选 input/sources.json 显式声明多文件参考闭包，见[输入与可移植边界](docs/design_flow.md#输入与可移植边界)。原始文件逐份冻结并记录指纹，只读取文本及适用的语法/AST，不执行参考，不假定函数入口。

```sh
python3 harness/run.py architecture --validate-inputs
python3 -B -m unittest discover -s harness/tests
python3 harness/run.py architecture --run-id architecture-example
python3 harness/run.py architecture --resume architecture-example
```

## 职责

阶段交付是资源组织清楚、关键选择有工程依据、无已知关键矛盾、值得进入 RTL 探索的微架构草稿。允许典型路径、粗调度、有依据的保守利用率和估算范围；具体流水、完整逐拍排程、局部仲裁、尾部控制及完整位精确回归可在实现阶段细化。原始功能、预算与误差要求保持不变。

run.py 是唯一入口。stages/architecture.py 先启动source-only基线，再负责提取、设计、硬门、独立审阅、有限修订和终止。设计与审阅的方法、数据契约、计算及报告校验分别在两个 skill 中；prompts/architecture.py 只组装冻结输入、skill内容与协议。runtime/requirement_session.py、design_session.py 和 audit_session.py 负责请求、结果、修复反馈与恢复；source_evidence.py生成冻结原文位置目录；call_budget.py执行共享额度与最小审阅保留；run_store.py 管理输入快照、指纹、证据、锁和统一文档渲染。停滞比较覆盖全部机器声明，纯说明文字变化不计作进展。

adapters/omp.py 沿用 models.toml 的角色与已有 OMP 认证，使用同一CLI原生stdin传递完整提示文本与原有固定前缀，避免长argv限制；提示原文及实际wire指纹保存，不截断或另建客户端。模板须有一个独立{prompt}占位，嵌入式/多消息模板明确拒绝。omp_isolation.js 显式禁用全部原生工具/MCP，活动工具列表必须为空。计算由宿主执行固定脚本的受限文本请求完成，模型不能提交任意代码、路径或命令。提供者内部重试在CLI返回后计账，当前额度不构成提供者侧严格费用限制。

## 声明与计算

设计模型声明原始工作量、资源、成本依据和调度选择。唯一预算契约位于设计skill references/budget-tools.md；scripts/evaluate.py、source_quantities.py、budget_units.py、work_model.py、storage_model.py和execution_model.py 是可独立运行的标准库脚本包。固定规则生成实际宏容量、填充/总线流量、缓冲分配、宏与逻辑面积总计、输入时钟事实的Hz换算、完整任务周期及吞吐率；重复的派生输入字段和内建指标不被接收，不维护旧契约转换。

存储成本有输入密度时，直接绑定实际宏清单；未给时需要显式成本依据与不确定性。成本假设不是综合测量。完整任务周期来自声明的非重叠关键路径区间，计算区间可引用计算账本，避免抄写。必要下界不等于完整周期预测；模型须说明工作覆盖、依赖与重叠。

现有硬门检查引用、源数量绑定、显式单位转换、有限单位的量纲与前缀尺度、宏规则、计算下界、连续请求的在途/响应预留、由对象形状/位宽/副本/填充/元数据及合法域推导的同时存活容量、具体有限窗口的物理字请求/输入端口/读就绪、ABI位段和面积区间。它不证明清单完整、引用语义、完整重复/tail调度、实际bank地址映射和声明生命周期可行性、数值行为或物理闭合。流量模型只支持明确的连续预留响应与posted-write计账；选定方案使用未支持模型时 gate=unknown，报告工具能力缺口，不伪装成硬件不可行。

候选修订使用replace_candidates和真实design hash：模型提交带现有ID的完整候选，宿主整体替换并保留未提交候选；不合并字段或补齐遗漏，始终重算完整候选集、保留版本。改变候选集合需完整evaluate_design，不维护逐字段修改协议。数据错误未消除就不收最终正文；上限停止。合法硬预算超限仍可形成未接受的候选报告并审阅，不能交付。未满足的目标单独记录，不降低要求。

## 独立审阅与文档

最终设计回复只有实际复算hash与一份完整architecture.md；需求、候选、模块/连接、调度/状态、接口、数据交换约定/布局、数值路径、预算依据和RTL实施契约都在同一文档。结构化声明另行保存。宿主在审阅前附加实际预算表；审阅、草稿和导出使用同一渲染函数。模型正文不能由宿主手工修补。

审阅显式加载独立skill、原始输入、完整文档与程序结果，不继承设计对话。先检查工作/复制/重用、依赖/重叠及工具适用性，再复算关键成本。recompute使用共享可信算术引擎，计算记录不修改设计；lookup_source只查询冻结packet。

审阅报告需要原始输入和方案引用、实际计算观察、需求映射及具体意见。阻断问题应有可验证关闭条件，建议不阻断；未决定ABI/数值/必要调度不能伪装成后续条件，数值执行和物理时序证据可作为后续义务。报告验证检查证据存在和内部一致性，不能证明工程判断正确。

执行工具历史、当前报告修复反馈、previous_audit分开。revision_checks仅追踪明确提供的上一轮开放阻断ID；修复报告格式不启动架构修订。packet hash与design-data hash属于不同范围，宿主提供实际对应检查；hash一致不证明语义一致。checks/architecture.py负责放行，模型accept不能覆盖算术错误、硬预算超限或未计算的必需预算。计算有效与比较通过分别记录；recompute和check_proposal中已执行的失败比较都必须处置，相关纠正需要实际重算和来源依据，不能用另一个无关通过项关闭。有限执行窗口、未绑定的可选模板及未检查数值探针记入ledger.evidence_gaps，不单独阻止草稿交付；不将其改标为已验证。

只读诊断现行结构化方案：

```sh
python3 harness/run.py architecture --audit-design /path/to/design.json --run-id audit-example
```

诊断audit_completed仅表示有效报告完成，仍可能revise，不交付、不修改源方案。旧数据契约不会转换，需由设计模型重新生成现行声明。

## 运行边界

architecture.toml控制修订、工具请求、响应、总调用、超时、累计活动时间和停滞上限；上限不是通过条件。所有调用计账，恢复累计。技能源维护在RTLskill，运行只用harness/skills固定副本，manifest逐文件核验。显式更新：

```sh
python3 harness/tools/vendor_skills.py --source /path/to/RTLskill
```

更新输入、代码、skill、配置或feedback后开新run；恢复拒绝身份变化及证据篡改，历史运行保留。只有accepted_conditional_design导出正式architecture.md；失败保存版本证据，不证明预算不可行。通过仍不是RTL、数值、综合或物理时序完成。

`--feedback /path/to/feedback.json`可携带历史审阅。可选`native_revision_seed`只用于恢复完整旧方案及其原始需求声明：输入指纹必须相同，当前提取器重新执行原文数量选择、单位换算和推导，结果必须逐项等于旧方案需求。任何不一致都明确停止，不能映射事实ID或静默回退。通过后沿用现有修订入口，重新检查工作模型与全部候选；设计模型仍须请求新的计算才可提交Markdown。旧审阅和工具结果仅是可质疑的历史上下文，无当前放行权。未提供该恢复材料的feedback仍按历史意见处理。

复制harness、更换input可以启动同一流程；任意新输入的语义、存储口径或成本模型未必受支持。跨项目可移植性须用独立真实项目完整运行验证，合成用例和脚本脱离harness测试不能代替。当前不生成完整芯片RTL，不建设Readiness或PPA阶段。

## 工作语义与两步独立审阅

设计skill在需求提取后先生成work_model：当前输入支持的计算/条件/状态/移动/控制义务、依赖及成本工作负载。原始输入和硬预算冻结，工作模型属于可有依据修订的解释；每次版本与指纹保留。通用count recipe只覆盖明确支持的矩阵乘、逐元素、归约或显式自定义计数，不声称自动理解任意Python。cost_groups是唯一工作到成本/资源的声明；调度区间引用成本组，程序推导追踪表。工作负载quantity/unit只在work_model声明，候选不重复填写。首次候选调用提供程序复算的声明工作量汇总；汇总不证明工作语义。cost_groups.work_ids可用显式ID列表或精确unit/category选择器（可显式exclude），只展开当前工作负载活跃项，不推断资源或填补漏项；预算回执保留选择器与展开ID。程序推导运算量和资源下界加显式overhead；旧手填operations/scheduled_cycles不接受。融合与替代实现可声明transformed及等价依据，机械检查不证明等价。

设计工作模型的生成/修复在runtime/design_session内受有限响应和总调用额度约束，未通过不进入候选。跨候选使用同一模型；修订需work_model_revision原文依据。脚本包增加同目录work_model.py，仍只用标准库并可脱离harness执行。

controller在昂贵设计前调用runtime/audit_session的source-only入口，审阅模型，只提供同一冻结原始输入闭包和审阅skill，生成独立语义基线；这一步没有设计清单、架构、预算或历史审阅。基线结构与设计模型不相同，ID无需一致。程序验证原文引用、结构并执行源形状/范围计算后，第二个独立上下文调用收到基线、原文、完整架构和真实预算，核查语义与成本。最终报告requirements行的baseline_ids覆盖基线，不能用基线文本代替原始证据。

仅成功执行数量分析的基线按输入、skill、全部引用文档和审计/共享计算脚本闭包身份缓存；相同输入与方法下的架构修订可复用。baseline_corrections必须引用原始输入并明确解释修正，触发下一轮重建；基线错误不自动变成设计错误。原始引用和结构通过但数量 witness 失败时，保留失败记录并允许方案审阅独立举证缺陷或报告 insufficient_evidence；accept 仍必须有成功源分析和候选检查。引用存在与结构通过仍不证明基线完整或审阅正确。报告修复、基线修复与架构修订明确分开。

max_audit_baseline_repairs控制基线格式/证据修复，所有新调用共享原有max_model_calls和时间上限；本轮不增加总额度。controller只传执行配置并接收最终审阅报告，没有解释工作量、清单差异或计算公式。仍只交付一个architecture.md，内部清单与基线在证据中保存。

## 单JSON协议修复与失败反馈

OMP对完整的单JSON对象/协议帧支持语法修复，复用现有evidence角色；原始响应、修复响应与校验回执分别保存。严格扫描全部字符并验证完整对象，字段/值/顺序/嵌套必须守恒，数字按精确十进制比较；不补截断，不改Markdown，不把有效JSON的字段错误交给语法修复。修复计入总调用额度并使用原请求剩余时限。runtime保留原始检查，分类反馈格式/声明/资源矛盾/有效预算失败/未知证据；判断不改变放行门槛。停滞指纹纳入工作模型的数量、计数范围及依赖，仍是句法启发式，不证明自然语言更正没有工程价值。

源工作量使用element/task/prefix范围：每元素计数和整任务计数分开，变化前缀由程序做等差和；不接收旧repetitions。所声明范围是否对应Python仍需独立审阅。存储对象需求不接收手填required_bits，程序枚举声明合法整数域、逐phase求同时占用峰值，并检查共享宏合计。超过工具枚举上限保留unknown。有限执行窗口从实际宏字请求派生端口占用，允许打包与广播，检查同步读就绪；无法表达的服务模型显式unknown，不能证明完整流水调度。

证据引用首选模型明确选择的file/start/end范围，由程序读取冻结原文并派生稳定evidence ID；检查回执保存范围到原文/指纹的绑定，模型报告本身不改写。返回的ID也可原样引用；提示不再要求抄写逐行长hash目录。稳定ID绑定文件内容、原文范围与引用。基线引用局部修复仅替换错误引用；报告修复由宿主绑定实际当前版本，限定引用、topic/覆盖行，禁止改变verdict、findings内容和执行观察。工程意见改变需新的审阅版本。max_design_format_repairs、max_audit_report_repairs限制各自格式响应，reserved_audit_calls/seconds在既有总额度内为方案审阅保留最小机会；保留不保证报告一定完成，所有额外调用照常计账。

仅在完整报告校验后只剩一项`checks.evidence`文本类型错误时，允许一次精简修复输入，保留完整原报告、相关原文绑定和执行引用。宿主不改字段或推导内容，修复仍经过完整原packet校验；失败后恢复完整上下文。引用错误、工程重审、混合或未知错误始终使用完整上下文，所有修复共享原额度。

需求提取使用source选择冻结原文的file/line/number（全部一基），脚本绑定原始数值及附着单位；无附着单位时模型声明语义单位，仍需审阅。单位换算用convert而非手填倍率，formula用于工程推导；源入口不接受value或程序专用converted_from。REQUIREMENTS_REPAIR绑定原始声明hash，整行替换或新增；remove_fact_ids只按模型明确要求删除且拒绝遗留依赖。不合并字段、不猜值。原始回复、声明、解析结果、数量表与绑定回执分别保存和冻结，恢复从原始声明重放。引用越界反馈实际范围及有限原文上下文，仍由模型选择引用，程序不裁剪。审阅的revise必须有未关闭的阻断缺陷；仅有条件和建议不要求设计修订。insufficient_evidence停止审阅证据阶段，不自动重做架构。协议报错列出实际多余字段，request_id由宿主赋予。

## 独立定量核验与修复边界

源基线入口只加载 source-baseline.md 协议，模型提取义务和少量关键形状/范围/逻辑状态/外部字段。source_model.py 按事实、profile及计算/状态/流量的逐profile事务执行固定代数；失败依赖不进入有效视图，无关成功证据保留。完整覆盖对照原始声明全域核验，不依赖父标志。单一 scope 配方在原始profile上展开，移除逐profile嵌套声明。范围、单位、输入编码和算法含义仍由模型独立判断；计数不是普适硬件下界。候选和源可分别按RUN或元素计根数量，同一完成边界内实际操作量和流量才是比较对象。源数量不完整时可用成功交易举证局部缺陷，但禁止accept和基线缓存。模型收到 verified_data 紧凑视图，完整收据/身份及失败诊断仍保存。

check_proposal 复算真实候选并核对工作对应、固定有效载荷、服务区间的共享资源累计需求和所有活跃lane的操作数证据；合法重叠、打包和寄存器广播不被预设为冲突。混合primitive单位融合必须保留各单位总数和独立等价说明，不作直接数值相加或自动通过。有限窗口不证明完整重复/尾部调度，选定表示和原始逻辑状态对应仍需实质审阅。check_proposal 以独立 count/flow/service/operand 事务保存实际证据；一个坏声明不删除其他成功反例。执行与子回执绑定完整输入、源解释、设计、预算和脚本闭包，顶层数值严格是成功子项并集。accept需要真实绑定的候选检查与独立计算观察，工具未穷尽所有profile/count/flow/operand本身不阻止草稿；审阅仍须判断主要资源、状态与预算是否成立，并处理每个已执行失败。能力未定与服务声明缺失分开。变换路径用形状/范围配方检查实际成本组、资源速率及周期，独立realization_reviews引用该交易证据并解释语义/数值对应；这是模型审阅，不是程序证明。合法零算术路由/融合不被源计数相等规则误拒。

固定外部流使用同向流组对应打包传输，分别比较实际绑定载荷和完整已声明候选库存。有效载荷与wire padding分开，非字节字段只求必要位下界，零活动可对应零传输。未知/不完整库存不作必然缺口。每个有效执行失败在所有最终verdict中均须counterexample_reviews明确处置：设计缺陷必要修订；审阅者错误引用同源路径/任务/单位的相关实际通过检查；源解释错误指向受影响声明、任务或实际事实依赖并显式纠正，未执行纠正不支持accept。反例使用真实request/receipt/check定位实际证据，数值观察另需真实计算ID与匹配值；不重复要求抄写反例数值ID。局部负面报告的未映射基线/约束由程序明确列出，accept仍需覆盖原始义务与约束的工程评审映射，无须穷尽全部工具关系。程序只检查追踪和关系，不证明报告语义。

源事实/单位转换复用可信计算闭包；原文引用跨度由程序绑定。数量视图明确标明附着单位及未附单位的声明义务，不自动推断语义单位。bit/bits等同值存储拼写可规范化，倍率或语义变化仍需显式转换。基线引用错误只修引用，analysis错误且义务已通过时只替换完整analysis并记录source_revision。报告引用可按topic/id替换整数组，判断冻结。独立声明错误同次汇总，减少分步格式消耗；所有调用仍计入既有额度。

遗漏独立基线映射、非法状态枚举和尚未解决的设计决定不能用引用补丁修复；结构可校验且执行观察安全时，runtime 在原剩余额度内只重新请求模型完整判断，不自动补映射或改观察值。审阅模型不回填 packet/baseline/修复目标身份；这些由宿主绑定输入快照、真实 raw/parser 响应、解析内容和当前 canonical 版本。模型提交保留身份字段会被拒绝，恢复重验实际响应和执行证据。伪造计算与实际执行矛盾继续被拒绝。缺少实际放行证据时，runtime 在同一 packet 和剩余工具/总额度内重新请求审阅判断，不消费只能修引用的响应。已执行的未知服务能力遗漏披露也需要重新判断，可复用已有回执；工具已用完且实际证据仍缺失则停止。首报告前的响应上限只适用于从未有报告的运行，重新判断不重置任何上限。
